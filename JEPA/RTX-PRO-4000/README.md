# CacheWave Inspector: JEPA edge node (RTX PRO 4000)

Triton Python-backend model `vjepa_inspect` that guides a technician to photograph a **license plate, battery and brake**. One frozen V-JEPA 2 encoder feeds a small trained head per item. The Android app (`/app`) sends frames and gets back a 12-number guidance vector.

Box this was built and run on: Intel Xeon E-2478 + NVIDIA RTX PRO 4000 Blackwell SFF, Docker with `nvcr.io/nvidia/tritonserver:25.09-py3`.

## What is in this folder

| Path | What |
|---|---|
| `triton_model_repo/vjepa_inspect/` | The deployed model: `config.pbtxt`, `1/model.py`, `plate_logic.py`, `obj_logic.py` and the three trained heads `plate_head.pt`, `brake_head.pt`, `battery_head.pt` (about 16 MB each) |
| `deploy/` | Container launch notes, `requirements-serving.txt`, `requirements-training.txt`, the Avahi (mDNS) service file the app uses to find the node |
| `training/` | Synthetic data generators, feature extraction, head training, threshold analysis |
| `tests/` | End-to-end tests against the live endpoint and the latency/emulation benchmarks |
| `eval/` | Held-out metrics and logs from training and benchmarks |

**Not in this repo:**
- The V-JEPA 2 encoder weights (about 1.3 GB). The model loads `facebook/vjepa2-vitl-fpc16-256-ssv2` from Hugging Face by id on first start.
- Training data and cached features (synthetic clips, `.pkl`/`.npy` feature files, videos). They are regenerated by the scripts in `training/`.
- Older experiments (`vjepa_plate`, `vjepa_scorer`, `vjepa_guidance`) and `battery_head_v1.pt`.

## Wire format

`POST /v2/models/vjepa_inspect/infer` on port 8000, KServe v2 binary protocol (input `FRAMES` uint8, output `GUIDANCE` fp32 x12).

`FRAMES` = `[task:1][n:1]` + n x `([len:4 big-endian][JPEG 256x256])`
- `task`: 0 brake, 1 battery, 2 plate, 3 auto (any of the three). Bit 7 set = verify a captured still (more tolerant).
- The model uses the last 16 frames (even count, at least 4).

`GUIDANCE` = `[code, ready, dx, dy, size, brightness, sharpness, motion, present_prob, done_prob, infer_ms, frames_used]`
- `code`: 0 OK, 1 DARK, 2 BRIGHT, 3 BLURRY, 4 SHAKY, 5 LEFT, 6 RIGHT, 7 UP, 8 DOWN, 9 CLOSER, 10 BACK, 11 WARMING, 12 ERROR, 13 NO_PLATE (target not in view, used for every item), 14 ADJUST, 15 COVERED.
- In auto mode, `done_prob` slot carries the detected task (-1 = nothing found).

## Deploy

1. Install Docker with the NVIDIA runtime. Put this folder's `triton_model_repo` somewhere, for example `~/vjepa-bench/triton_model_repo`.
2. Create the container (it is a plain `sleep infinity` container; Triton is started inside it):
   ```
   docker run -d --name triton --gpus all --shm-size=8g \
     -p 8000:8000 -p 8001:8001 -p 8002:8002 \
     -v ~/vjepa-bench/triton_model_repo:/models \
     -v ~/.cache/huggingface:/root/.cache/huggingface \
     nvcr.io/nvidia/tritonserver:25.09-py3 sleep infinity
   ```
3. Install the Python packages inside the container (see `deploy/requirements-serving.txt`; the image sets `PIP_BREAK_SYSTEM_PACKAGES=1`):
   `docker exec triton pip install -r /path/to/requirements-serving.txt`
4. Start Triton inside the container:
   `docker exec -d triton tritonserver --model-repository=/models`
5. For automatic discovery by the phone app, copy `deploy/cachewave-triton.avahi.service` to `/etc/avahi/services/`. The app looks for `_cachewave-triton._tcp`.

Steps 3 and 4 are reconstructed from the container's settings and installed packages; the exact original launch command was not recorded. If the container loses GPU access ("Failed to initialize NVML"), `docker restart triton` and start Triton again.

## Known limits

- The three heads were trained on **synthetic** scenes only. On three real battery photos tested, the battery head recognised two. Real-photo fine-tuning has not been done for JEPA.
- Two stopgaps for real photos live in `model.py` and `obj_logic.py`: the battery box is shrunk by `BOX_SCALE = 0.45`, and the battery "complete" threshold is `DONE["battery"] = 0.0`, so only presence, size and framing decide for batteries.
- Verify mode (task bit 7) uses a looser margin (-0.10), `done_thr` 0.0 and `present_thr` 0.40.

## Training pipeline (order)

1. `synth_plates.py`, `synth_objects.py`: synthetic scene generators.
2. `build_features.py` (plate) and `build_features_obj.py` (battery, brake): cache frozen V-JEPA 2 time-mean patch tokens.
3. `train_head.py` (plate) and `train_obj.py` (battery, brake): train a head, write `<task>_head.pt` and `<task>_eval.json`.
4. `eval_thr.py`, `auto_neg.py`, `auto_thr.py`: threshold and false-positive analysis, including auto mode.
5. Copy the `*_head.pt` files into `triton_model_repo/vjepa_inspect/1/` and restart Triton.

`train_local.py` and `gen_single.py` are an earlier experiment (a small single-frame MobileNetV3 for on-device use) and are not part of the deployed model.
